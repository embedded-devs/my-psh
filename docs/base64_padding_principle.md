## 一、 背景概述

在 PSH（Protect Shell）安全解锁模块中，设备通过 `debug` 命令生成**挑战码**（Base64 编码的 RSA 密文），管理员远程解密后派生出**短密钥**（8 字符短密钥），用户输入短密钥完成解锁。

原始实现中，挑战码以 `==` 结尾、短密钥以 `=` 结尾，在输入和展示时不够简洁。经优化后，挑战码仅含 1 个 `=`，短密钥不含任何 `=`。

## 二、 Base64 填充原理

### 1. 编码规则

Base64 将每 3 个字节（24 bit）编码为 4 个字符（每字符 6 bit）。当输入字节数不是 3 的倍数时，用 `=` 填充至 4 的倍数：

| 输入字节数 % 3 | 填充 `=` 数量 | 示例 |
|:-:|:-:|:-:|
| 0 | 无 `=` | 3 字节 → 4 字符 |
| 1 | `==` | 1 字节 → 2 字符 + `==` |
| 2 | `=` | 2 字节 → 3 字符 + `=` |

【**关键结论**】`=` 的数量完全由**原始字节数对 3 的余数**决定，与内容本身无关。

### 2. 数学验证

- **256 字节**：256 ÷ 3 = 85 余 **1** → 末尾 `==`
- **257 字节**：257 ÷ 3 = 85 余 **2** → 末尾 `=`
- **5 字节**：5 ÷ 3 = 1 余 **2** → 末尾 `=`
- **6 字节**：6 ÷ 3 = 2 余 **0** → 无 `=`

## 三、 挑战码优化：双等号变单等号

### 1. 原始方案

RSA-2048 加密产生 256 字节密文，直接 Base64 编码：

```
256 字节密文 → Base64 → 344 字符，末尾 "=="
```

256 % 3 = 1，因此产生 2 个 `=` 填充。

### 2. 优化方案

在密文前添加 **1 字节版本前缀**（值为 `0x00`），使总字节数变为 257：

```
1 字节前缀 + 256 字节密文 = 257 字节 → Base64 → 344 字符，末尾 "="
```

257 % 3 = 2，仅产生 1 个 `=` 填充。

### 3. 代码变更

在 `func_unlock_generate_challenge()` 中，Base64 编码前拼接版本前缀：

```c
uint8_t prefixed[1 + UNLOCK_CIPHER_SIZE];
prefixed[0] = 0x00;                                    /* 版本前缀 */
memcpy(prefixed + 1, ciphertext, cipher_len);           /* 密文 */
func_base64_encode(prefixed, 1 + cipher_len, b64_out, b64_size);
```

对应宏定义（`func_unlock.h`）：

```c
#define UNLOCK_CIPHER_PREFIX_SIZE   1
#define UNLOCK_CIPHER_PREFIX_VER    0x00
```

### 4. 解码侧适配

管理端 `unlock.sh` 在 Base64 解码后，需跳过首字节再执行 RSA 解密：

```bash
printf '%s' "$CHALLENGE" | base64 -d | tail -c +2 | openssl pkeyutl -decrypt ...
```

## 四、 短密钥优化：去等号

### 1. 原始方案

HMAC-SHA256 输出取前 5 字节，Base64 编码为 8 字符（含 1 个 `=`）：

```
5 字节 → Base64 → "aGJjZGU="（8 字符，含 '='）
```

5 % 3 = 2，产生 1 个 `=` 填充。

### 2. 优化方案

HMAC-SHA256 输出取前 **6 字节**，Base64 编码仍为 8 字符（无 `=`）：

```
6 字节 → Base64 → "aGJjZGVm"（8 字符，无 '='）
```

6 % 3 = 0，无需填充，不产生 `=`。

### 3. 代码变更

修改 `func_unlock.h` 中的宏定义：

```c
/* 修改前 */
#define UNLOCK_SHORT_KEY_BYTES      5

/* 修改后 */
#define UNLOCK_SHORT_KEY_BYTES      6
```

### 4. 安全性影响

| 指标 | 5 字节 | 6 字节 |
|:-:|:-:|:-:|
| 密钥空间 | 2^32 ≈ 43 亿 | 2^48 ≈ 2.8 万亿 |
| Base64 长度 | 8 字符（含 `=`） | 8 字符（无 `=`） |
| 暴力破解难度 | 配合 5 次限制已足够 | 提升 65536 倍，更安全 |

## 五、 完整数据流对比

### 1. 修改前

```
挑战码: [256 字节密文] → Base64 → "xxx...yyy=="  （2 个 '='）
短密钥: [5 字节 HMAC]  → Base64 → "aGJjZGU="     （1 个 '='）
```

### 2. 修改后

```
挑战码: [1 字节前缀 + 256 字节密文] → Base64 → "xxx...yyy="  （1 个 '='）
短密钥: [6 字节 HMAC]               → Base64 → "aGJjZGVm"     （0 个 '='）
```
